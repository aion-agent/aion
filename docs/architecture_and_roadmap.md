# Aion Project: Architecture & Roadmap

## 1. System Architecture
Aion is a local AI agent written in Rust, built to orchestrate large language models (specifically `llama.cpp` serving the Hermes series) through persistent memory and dynamic external tools. 

### Core Components
- **Agent Core (`src/agent_direct.rs`)**: Manages the HTTP client interacting with the local LLM endpoint. It maintains the conversational history, handles the ChatML formatting, and manages the execution loop for tool processing.
- **Configuration Parser (`src/config.rs`)**: Deserializes `root.toml` to dynamically inject the `model`, `temperature`, `max_tokens`, and `base_url` into the agent's LLM payload.
- **Memory System (`src/memory/`)**: A hierarchical, `rusqlite`-backed memory store. It supports FTS5 full-text search natively. A unique feature is that the root database can summon isolated "child databases" (scopes) for compartmentalizing specific projects. 
- **Tool Calling System (`src/tool_call/`)**: Parses, routes, and executes function calls generated by the LLM.

---

## 2. The Hermes Tool Calling Protocol
Aion communicates with the model using an XML-based ChatML framework tailored for Hermes models.

1. **Detection**: The `extract_tool_call` parser scans the LLM's raw string response for `<tool_call>` boundaries enclosing a JSON payload.
2. **Execution**: If detected, Aion extracts the JSON and passes the payload to `execute_tool()`.
3. **Response Feed**: The agent intercepts the LLM's conversational flow, executes the task, and artificially appends the outcome to the conversation history wrapped in a `<tool_response>` tag. 
4. **Recursive Loop**: Aion automatically re-prompts the LLM with this new tool response until the model answers conversationally without invoking a tool.

## 3. Creating External Integrations (Deno/JS)
External integrations are dynamically loaded at runtime from the `./integrations` directory, meaning Aion does not need to be recompiled when adding new skills.

### How Subprocess Tools Work
When an external tool is invoked, Aion utilizes a subprocess executor (`sh -c`). It takes the JSON arguments generated by the LLM and pipes them directly into the script's **`stdin`**. The script executes, and whatever it logs to **`stdout`** is returned to the agent.

To build a tool:
1. **The Integration Map (`.integration` TOML)**: Defines the tool name, points to the JSON schema, and declares the shell executor (e.g., `deno run -A tool.js`).
2. **The JSON Schema (`.json`)**: Standard OpenAI-style function schema so the LLM understands how to invoke the tool.
3. **The Script (`.js`/`.ts`)**: Reads `stdin`, processes the logic, and writes back via `stdout`.

**Deno Example Snippet**:
```javascript
const input = await new Response(Deno.stdin.readable).text();
const args = JSON.parse(input);
// ... process logic ...
console.log(JSON.stringify({ status: "success", data: "..." }));
```

## 4. Roadmap & Next Tasks
*Tasks to tackle in the next session to evolve Aion from a prototype to a production-ready agent:*

- `[ ]` **Robust Error Recovery**: Improve the LLM's ability to self-correct when `tool_response` returns an error (e.g., malformed JSON or missing parameters).
- `[ ]` **Long-term Context Window Management**: Implement a sliding window or summarization technique for `self.history` so the agent doesn't exceed the model's maximum context limit over long conversations.
- `[ ]` **Streaming Responses**: Refactor the `reqwest` HTTP client in `agent_direct.rs` to stream tokens to the user's CLI instead of blocking until the entire response is generated.
- `[ ]` **Real-World Integrations**: Build out practical Deno integrations (e.g., executing bash commands safely, reading/writing local files, web searches) utilizing the new subprocess standard.
- `[ ]` **System Prompt Refinement**: Optimize the `build_system_prompt` logic to give the Hermes model clearer, stricter instructions on how to leverage its child-databases and manage context.
